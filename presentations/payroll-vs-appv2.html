01Your two questions, answered

Does the current payroll need only one tx from the person initializing it — and then the backend distributes the amounts?

YES

The employer signs exactly one transaction: the funding deposit (sdk/src/client.ts:1568 → /api/relayer/submit). Every payout after that is signed by the relayer's own keypair — gasless, via /api/relayer/transact (workers/src/relayer.rs:115). The vault unlock is a free message signature, not a tx. Second run = zero popups.

Is a note generated for the user, for each employee?

YES

In shielded mode: one encrypted note per employee per payout — transferNoteInternal (sdk/src/client.ts:1188–1206), encrypted to the employee's x25519 key from the recipients registry. In public mode the row sends plain SOL instead — no note.

02Why this branch exists

This branch is the full payroll product direction: a real employer console, an employee app, and a gasless relayer backend — all running on the standard (stock) circuit, the same protocol the rest of privacy-cash uses. Its thesis, proven in STANDARD-CIRCUIT.md: payroll does not need custom batch circuits to ship. The batch3/batch5 work is a 5.6× speed optimization (11–13s vs 63–81s per 210 employees), not a prerequisite. That is why it matters: it decouples "we can launch" from "we finished the fast prover."

05What we have to do — making payroll the primary app

blocker

Nothing is merged

This branch is 143 commits ahead of main and now verified (build + 43 tests green). Becoming "the primary app" starts with the merge decision — a PR from payroll-standard-circuit into main.

build

Move the fast path into the app

The batch3/batch5 circuits and the 0.28s arkworks prover live only under payroll/rust-prover-bench/. The shipped app still proves the stock circuit client-side (~63–81s per 210 employees). Wiring batched proofs into the SDK/UI is the one real engineering gap — and it's an optimization, not a launch requirement.

build

Transaction history page

Neither app has one. Payroll has per-row receipts + explorer links but they're localStorage-only. A server-backed history (the D1 mirror already indexes every tx) would close the biggest shared gap.

polish

Port the verification setup

app-v2's verification/ (Lean/Kani) and its architecture doc are worth carrying over so the primary app keeps the formal-verification story.

polish

Onboarding safety rails

Defaults point at the production backend and mainnet program — a fresh machine must switch Settings → Local simnet (covered in DEMO.md). Also pin the SDK's dependency install: today's build break was sdk/node_modules drifting to @noble/curves@2.4.0 against its own ^1.9.7 manifest; a reinstall fixed it.

polish

Employee app install

payroll/employee-app/ has no node_modules on this machine yet — one bun install away from running. Its SDK copy also needs a refresh whenever sdk/ changes (file: dependency).
